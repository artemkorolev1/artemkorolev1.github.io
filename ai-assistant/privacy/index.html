Privacy Policy

Last updated: October 20, 2026

About this application

ai-assistant is a personal automation application operated by Artem Korolev for his own use. It connects Google services to workflows running in n8n or similar automation software. It is not currently offered for public registration.

Google data accessed

Depending on the permissions granted and the workflow being run, the application may access Gmail messages and attachments, Google Drive files and their contents, and Google Calendar calendars and events. It may also create or update information when an authorized workflow requires it.

Access is limited by the Google OAuth permissions granted to the application. Not every workflow uses every permission.

How data is used

Google data is used to perform personal automation tasks, such as finding information, organizing files, processing email, and managing calendar events.

Processing and sharing

The current integration runs locally on the operator's Linux computer. Retrieved Google data is processed locally and is not sent to external cloud AI model providers.

The application communicates with Google to authenticate and carry out authorized API requests. Publishing this website through GitHub Pages does not upload the integration's Google data or OAuth credentials to the website.

If the integration moves to a cloud server or its data-sharing practices change, this policy will be updated before that change.

Storage and retention

OAuth credentials and tokens are stored by the locally operated integration so it can access the authorized Google services without repeated sign-in.

Depending on the automation platform's settings, workflow execution history, logs, temporary files, or outputs may contain retrieved Google data. A fixed retention period has not yet been established. Stored information can be removed by the operator through the integration's storage and logging controls.

Revoking access and deleting data

Google access can be revoked through Google Account connections . Revocation prevents further authorized access but does not automatically delete previously stored workflow data. Stored credentials, execution history, and outputs must be deleted separately from the integration and any backups.
